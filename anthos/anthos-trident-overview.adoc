= Trident Übersicht
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Trident ist ein vollständig unterstützter Open-Source-Speicherorchestrator für Container und Kubernetes-Distributionen, einschließlich Anthos.  Trident funktioniert mit dem gesamten NetApp Speicherportfolio, einschließlich NetApp ONTAP, und unterstützt auch NFS- und iSCSI-Verbindungen.  Trident beschleunigt den DevOps-Workflow, indem es Endbenutzern ermöglicht, Speicher von ihren NetApp -Speichersystemen bereitzustellen und zu verwalten, ohne dass ein Speicheradministrator eingreifen muss.

Ein Administrator kann basierend auf den Projektanforderungen und Speichersystemmodellen eine Reihe von Speicher-Backends konfigurieren, die erweiterte Speicherfunktionen ermöglichen, darunter Komprimierung, bestimmte Datenträgertypen und QoS-Stufen, die ein bestimmtes Leistungsniveau garantieren.  Nachdem sie definiert wurden, können diese Backends von Entwicklern in ihren Projekten verwendet werden, um Persistent Volume Claims (PVCs) zu erstellen und bei Bedarf persistenten Speicher an ihre Container anzuhängen.

image:a-w-n-astra-trident.png["Abbildung, die einen Eingabe-/Ausgabedialog zeigt oder schriftlichen Inhalt darstellt"]

Trident hat einen schnellen Entwicklungszyklus und wird wie Kubernetes viermal im Jahr veröffentlicht.

Die link:https://docs.netapp.com/us-en/trident/index.html["Trident Dokumentation"^]aktuellsten Versionsinformationen sind in der Dokumentation verfügbar. Eine Supportmatrix zur Trident Version-Kompatibilität mit Kubernetes-Distributionen ist in link:https://docs.netapp.com/us-en/trident/trident-get-started/requirements.html#supported-frontends-orchestrators["Unterstützte Frontends (Orchestratoren)"^]verfügbar.

Ab der Version 20.04 wird die Trident -Einrichtung vom Trident -Operator durchgeführt.  Der Operator erleichtert groß angelegte Bereitstellungen und bietet zusätzliche Unterstützung, einschließlich Selbstheilung für Pods, die als Teil der Trident -Installation bereitgestellt werden.

Mit der Version 22.04 wurde ein Helm-Diagramm zur Verfügung gestellt, um die Installation des Trident Operators zu vereinfachen.

Siehe link:https://docs.netapp.com/us-en/trident/trident-install/kubernetes-deploy.html["Trident Installationsdetails"^] für weitere Informationen.



[[create-a-storage-system-backend]]
== Erstellen Sie ein Speichersystem-Backend

Nach Abschluss der Installation des Trident Operators muss das Backend für die spezifische NetApp Speicherplattform, die Sie verwenden, konfiguriert werden. Der folgende Link führt zur Fortsetzung der Einrichtung und Konfiguration von Trident. link:https://docs.netapp.com/us-en/trident/trident-use/backends.html["Erstelle ein Backend"^]



[[create-a-storage-class]]
== Erstellen einer Speicherklasse

Nach dem Erstellen des Backends ist eine Speicherklasse zu erstellen, die von Kubernetes-Benutzern angegeben wird, wenn ein Volume benötigt wird. Kubernetes-Benutzer stellen Volumes mithilfe von Persistent Volume Claims (PVCs) bereit, die eine Speicherklasse anhand ihres Namens angeben. Über den folgenden Link kann eine Speicherklasse erstellt werden. link:https://docs.netapp.com/us-en/trident/trident-use/create-stor-class.html["Erstellen einer Speicherklasse"^]



[[dynamically-provision-a-volume]]
== Dynamisches Bereitstellen eines Volumes

Sie müssen ein Kubernetes Persistent Volume Claim (PVC)-Objekt mithilfe der Storage-Klasse erstellen, um ein Volume dynamisch bereitzustellen. Über den folgenden Link kann ein PVC-Objekt erstellt werden. link:https://docs.netapp.com/us-en/trident/trident-use/vol-provision.html["Erstellen eines PVC"^]
